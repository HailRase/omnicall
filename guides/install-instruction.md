# Axatalk — установка и первый звонок

Инструкция для конечных пользователей и для тех, кто собирает установщики для распространения.

**Ежедневная работа в приложении:** [`User-Guide-RU.md`](User-Guide-RU.md)

---

## 1. Что нужно пользователю

| Требование | Подробности |
| --- | --- |
| ОС | Windows 10/11, macOS 12+, Ubuntu 22.04+ (или аналог с glibc) |
| Сеть | Доступ к SIP-серверу по WebSocket (`ws://` или `wss://`) |
| Учётная запись | Логин, пароль, домен и адрес SIP-сервера от администратора |
| Микрофон | Разрешение на использование микрофона (запросит ОС при первом звонке) |

---

## 2. Скачивание установщика

**Релизы для пользователей:** https://github.com/HailRase/axatalk-releases/releases/latest

Готовые файлы также лежат в `dist/win`, `dist/mac` или `dist/linux` после локальной сборки (или в артефактах GitHub Actions).

| Платформа | Файл | Формат |
| --- | --- | --- |
| Windows | `Axatalk-<версия>-win-x64.exe` | NSIS-установщик (пользователи) |
| Windows (IT) | `Axatalk-<версия>-win-x64.msi` | MSI — тихая установка, GPO (`msiexec /i … /quiet`) |
| macOS | `Axatalk-<версия>-mac-arm64.dmg` или `-mac-x64.dmg` | Образ диска |
| Linux | `Axatalk-<версия>-linux-x86_64.AppImage` (CI) | **Рекомендуется** — без App Center |
| Linux (Debian/Ubuntu) | `Axatalk-<версия>-linux-amd64.deb` | Для IT; ставить через **терминал** или GDebi |

Скачайте файл под свою ОС и разрядность (обычно `x64` / `amd64` / `x86_64`).

**Важно для `.deb` на Ubuntu:** двойной клик открывает **App Center** (карточку пакета). Окно может **само закрыться через несколько секунд** — это не Axatalk. Устанавливайте командой `sudo apt install ./файл.deb` или через GDebi.

## 3. Установка

### Windows

1. Запустите `.exe` (или `.msi` для корпоративной установки).
2. При предупреждении SmartScreen выберите «Подробнее» → «Выполнить в любом случае» (для неподписанных сборок).
3. Укажите папку установки или оставьте по умолчанию.
4. Завершите мастер; ярлык появится на рабочем столе и в меню «Пуск».

### macOS

1. Откройте `.dmg` и перетащите **Axatalk** в **Applications**.
2. При первом запуске: **Системные настройки** → **Конфиденциальность и безопасность** → «Всё равно открыть» (если приложение не подписано сертификатом Apple).
3. Разрешите доступ к микрофону, когда система спросит.

### Linux (AppImage)

```bash
chmod +x Axatalk-*-linux-x64.AppImage
./Axatalk-*-linux-x64.AppImage
```

При необходимости интегрируйте в меню через [AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher).

### Linux (.deb)

**Не полагайтесь на двойной клик.** На Ubuntu 24.04 окно **App Center** часто показывает карточку пакета и **само закрывается через несколько секунд** — до кнопки «Установить». Это сбой GUI-установщика ОС, не Axatalk.

**Рекомендуемый способ** — терминал (подтянет зависимости):

```bash
cd ~/Downloads
sudo apt install ./Axatalk-*-linux-amd64.deb
```

Альтернатива: **GDebi** (`sudo apt install gdebi`, затем `gdebi ./Axatalk-….deb`).

Если App Center нужен: **один** клик по файлу (не два подряд), при необходимости `sudo snap refresh snap-store`.

После установки запускайте **Axatalk** из меню приложений.

Если App Center закрывается — используйте **AppImage** из того же Release (см. выше) или команды выше.

Если **само приложение** закрывается после запуска из меню — см. [`Developer-Release-CI-Guide.md`](Developer-Release-CI-Guide.md) (sandbox / AppArmor).

## 4. Первый запуск и регистрация SIP

1. Запустите **Axatalk**.
2. Дождитесь загрузки (экран «Booting application…» исчезнет).
3. Нажмите на **аватар пользователя** в шапке → **Настройки**.
4. Откройте раздел **Аккаунт** (если не открыт по умолчанию).
5. Заполните поля:

| Поле | Пример | Пояснение |
| --- | --- | --- |
| Имя пользователя | `1001` | SIP-логин (extension) |
| Пароль | `••••••` | Пароль от SIP-аккаунта |
| Домен | `pbx.example.com` | SIP-домен (хост PBX) |
| Сервер | `wss://pbx.example.com:7443` | WebSocket URL до SIP (также допустимы `host:port`, `https://…`) |

6. Нажмите **Авторизоваться**.
7. В шапке статус должен смениться на зарегистрированный SIP (без ошибки регистрации).

При ошибке проверьте логин/пароль, домен, URL сервера и что файрвол не блокирует WebSocket.

---

## 5. Исходящий звонок

1. Убедитесь, что SIP зарегистрирован.
2. Откройте **панель набора номера** (кнопка с клавиатурой в зоне управления звонком).
3. Введите номер (внутренний или внешний — как настроено на PBX).
4. Нажмите кнопку вызова на панели набора.
5. Разрешите доступ к **микрофону**, если браузерный/Electron-диалог появится впервые.

---

## 6. Входящий звонок

При входящем вызове отобразится экран звонка с кнопками **Ответить** и **Отклонить**. Ответьте и говорите в микрофон.

## 7. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Не регистрируется SIP | Сервер, порт, `wss` vs `ws`, сертификат TLS, учётные данные |
| Нет звука | Микрофон в настройках ОС; устройство вывода по умолчанию |
| Windows блокирует установку | Подпись кода или SmartScreen (см. п. 3) |
| macOS не открывает приложение | Разрешение в «Конфиденциальность и безопасность» |
| Linux AppImage не стартует | `chmod +x`, FUSE/libfuse2 на старых дистрибутивах |

Диагностику для администратора: **Настройки** → **Диагностика** (логи приложения).

## 8. Сборка установщиков (для разработчиков)

### Предварительные требования

- Node.js 22+
- `npm ci`
- Сборка **на той же ОС**, для которой нужен установщик (Windows → `.exe`, macOS → `.dmg`, Linux → `.AppImage`/`.deb`), либо GitHub Actions workflow `.github/workflows/release.yml`.

### Команды

```bash
npm ci
npm run test          # рекомендуется перед релизом

# установщик для текущей ОС:
npm run build:win     # Windows NSIS
npm run build:mac     # macOS DMG
npm run build:linux     # Linux AppImage + deb

# артефакты (пример для Windows):
ls dist/win/
```

Production-сборка включает `VITE_ADAPTER_MODE=real` (файл `.env.production`) — в установщик попадают **реальные** SIP-адаптеры, не mock.

### Релиз через GitHub (автоматически)

Подробно: [`Developer-Release-CI-Guide.md`](Developer-Release-CI-Guide.md), [`RELEASE-PLAYBOOK.md`](RELEASE-PLAYBOOK.md).

1. `npm run release:preflight`
2. CHANGELOG + bump `version` в `package.json`
3. `npm run release:sync-manifest`
4. Commit `chore(release): cut vX.Y.Z` → push **`main`**
5. `git tag vX.Y.Z` → `git push origin vX.Y.Z`
6. CI workflow **Release** соберёт win/mac/linux и опубликует assets в GitHub Release

Manifest в `main` должен быть **до** push тега — тогда in-app проверка обновлений сразу видит новую версию.

Ручная загрузка бинарников не нужна, если CI зелёный.

### Иконка приложения

Положите `build/icon.png` (512×512 или 1024×1024) перед публичным релизом — см. `build/README.md`.

### Подпись кода (рекомендуется для продакшена)

| Платформа | Заметка |
| --- | --- |
| Windows | Authenticode-сертификат для NSIS |
| macOS | Apple Developer ID + нотаризация |
| Linux | Опционально GPG для `.deb` |

Без подписи приложение работает, но ОС могут показывать предупреждения при установке.

## 9. Системные требования к SIP-серверу

- Поддержка SIP поверх WebSocket (JsSIP).
- Корректный TLS-сертификат для `wss://` (или явный `ws://` в доверенной сети).
- Учётная запись с правом регистрации и звонков.

---

## 10. Проверка обновлений

В приложении: **Настройки → Общее → О программе → Проверить обновления**.

- Приложение **не ставит** обновление само — открывает страницу скачивания.
- Работает после публикации manifest на `main` и production-сборки с `VITE_UPDATE_MANIFEST_URL`.
- Подробнее: [`User-Guide-RU.md`](User-Guide-RU.md), раздел 9.

## 11. Версия и поддержка

Версия приложения: поле `version` в `package.json`; в UI — раздел **О программе** в настройках.

По вопросам настройки PBX обращайтесь к администратору телефонии; по установке клиента — к поставщику сборки.
