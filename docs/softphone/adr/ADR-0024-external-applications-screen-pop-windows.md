# ADR-0024: External Applications screen-pop BrowserWindows

- Status: **Accepted** (2026-07-31; amended 2026-08-02 — guest close-guard preload)
- Context: Operators need configurable CRM/helpdesk pages on call events inside Electron, not only system browser tabs (F-020) or HTTP webhooks (F-031). Card pages also need optional close validation without softphone knowing card fields.
- Decision: Main opens sandboxed `BrowserWindow` via typed IPC; payload is a resolved HTTPS URL + size/title/ids; child loads URL directly (no `<webview>`); partition `persist:external-applications`; duplicate `applicationId:callId` focuses existing window. Guest windows use a **minimal** preload (`externalApplicationGuest`) that exposes only `window.omnicall.setCloseGuard` / `clearCloseGuard` for optional close interception; not the main softphone preload / product IPC surface. Guest preload is built as a self-contained CJS entry (no shared chunks with main preload) because sandboxed Electron preloads break on `require("./chunks/…")`.
- Close-guard rules: native Close → query guest → explicit `true` closes; missing guard keeps prior unrestricted close; deny / throw / timeout fail-closed; call-ended `close` and dispose/destroy force-close without the guard.
- Alternatives rejected: iframe host page (X-Frame-Options failures); `<webview>` (deprecated / larger attack surface); unvalidated renderer `window.open`; softphone HTTP close-check that requires modeling foreign card fields; full softphone preload in guest.
- Consequences: Application resolves templates and validates HTTPS before IPC; Domain stays Electron-free; F-030 round-trips `UserSettings.externalApplications` (schema **v16**, conditions.queueNames + windowBehavior); open history is profile-local (not F-030); call-ended lifecycle uses second typed IPC and runs before terminal-event opens; integrators document close-guard in `P14-External-Applications-Design.md`.
